# wspai

`wspai` is a shorter command for the complete Workspai CLI. It runs the main
[`workspai`](https://www.npmjs.com/package/workspai) package, so both names
provide the same commands, features, and output files.

```bash
npx wspai --help
cd /absolute/path/to/project
npx wspai adopt .
```

The CLI creates or reuses the minimal default workspace and records a validated
link from the project. Adoption already seals initial Model, Graph and agent
grounding. You need Node.js 20.19+ and npm, as with the main package.
For a project task, stay in the same source terminal:

```bash
npx wspai agent context --project . --for-agent generic \
  --task "Find the main entry points and available project checks"
```

Check packet status and project scope before using its evidence. The packet
includes bounded Graph candidates, lifecycle commands and a compact project
Skill. Your host must load the generated instructions; prepared context alone
does not prove model use, edits or executed tests. Follow selection or budget
recovery before reading packet components.

Use `generic` for vendor-neutral context, or select `codex`, `claude`,
`cursor`, or `copilot`. Shared grounding for GitHub Copilot, VS Code, and
`AGENTS.md` consumers is generated by the same chain.

Use `npx wspai project workspace status --json` when you need the canonical
workspace path. Attached projects resolve their workspace automatically; use
the workspace root directly for intentionally workspace-wide operations.
After changes, request a full workspace refresh or CI gate when needed:

```bash
npx wspai workspace intelligence run --for-agent generic --strict --json
```

That run maps the system, records its connections and checks affected areas.
It is not an extra prerequisite for every task packet. `wspai` does not install
or maintain a second engine.

## Which package should I use?

- Use `workspai` in documentation, automation, CI, and long-lived scripts. It is
  the main package and command name.
- Use `wspai` when you prefer a shorter interactive command.

Installing the alias also installs the exact matching `workspai` version. Both
names use the same engine, configuration, `.workspai` files, and commands.

```bash
npm install -g wspai
wspai --version
```

The main package remains available directly:

```bash
npm install -g workspai
workspai --help
```

Workspace state and generated reports use the same `.workspai` directory
regardless of which command spelling you choose.
